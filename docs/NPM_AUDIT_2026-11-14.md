## patient-app, what npm reported
- **critical: `tinypool`** (prototype pollution leading to remote code execution), reached through `vitest`. Test tooling only; the fix is `vitest@5.1.0`, a breaking change.
- **moderate: `@vitest/mocker`, `vitest`, `vite`, `vite-node`, `esbuild`**: the dev-server and test tools. `esbuild` lets any website send requests to the *development* server; fix is `vite@8.3.8`, a breaking change.
- **moderate: `react-router` / `react-router-dom`** (open redirect, constructor injection in server-side rendering): fix is `react-router-dom@7.18.5`, a breaking change. The app does not do server-side rendering, so the second one does not apply as far as we know (not verified).
- **moderate: `glob`, `minimatch`, `deepmerge`** (and `@rollup/plugin-node-resolve`, `workbox-build` through them): `npm audit fix` (without `--force`) can fix these.

## What this means (plain)
- Most of it sits in dev and test tools, not in what a patient's browser runs. `react-router` is the one that ships to the browser.
- The fixes that need `--force` are major upgrades. They need a test run and are Jehal's call (patient app owner). Nothing was upgraded here.
- Dependabot is disabled on the repository, so nobody is told about new advisories.
